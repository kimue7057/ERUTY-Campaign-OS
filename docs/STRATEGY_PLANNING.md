# 전략 기간·예산 입력 보완

전략은 기존에 이름·정렬 순서만 저장했고 기간과 예산은 활동에만 있었다. 전략 추가·수정에 계획 시작일, 종료일, 예산 한도를 추가한다. PostgreSQL DATE와 nullable BIGINT로 기존 전략의 미설정 상태를 보존하며 기존 기간·예산을 임의로 채우지 않는다.

- 캠페인 총예산 한도는 고정된다. 2026-10-13 사용자 요청에 따라 캠페인 상단의 배정 예산은 전략 한도의 합계이며, 캠페인 남은 예산 = 캠페인 한도 − 전략 배정 합계이다. 전략 등록·수정·삭제에 따라 잔여를 다시 계산한다. 예산 미설정 전략은 합계에서 제외하고 개수를 표시하며 0원 설정과 구분한다.
- 전략 잔여 = 전략 한도 − 소속 활동 배정 합계. 활동 등록·수정·삭제는 전략 잔여에 반영된다. 전략 배정과 활동 계획을 캠페인 잔여에서 중복 차감하지 않는다. 활동 계획 API 집계와 선택적 세부 작업 중복 합산 방지 규칙은 유지한다.
- 전략 기간은 두 날짜를 함께 입력/해제하며 역전된 기간과 음수·원화 범위 초과를 서버/DB에서 차단한다. 날짜나 금액을 미설정한 기존 전략도 그대로 조회·편집한다. 예전 API가 새 필드를 생략하면 기존 값을 보존한다.
- 전략의 한도 초과·기간 밖 작업은 경고로 표시한다. 전략을 수정해도 기존 활동 날짜·예산을 자동 변경하지 않는다. 새 활동의 기본 날짜만 전략 기간을 사용한다.
- 개요에 캠페인 잔여, 전략 기간·한도·활동 배정·잔여를 표시한다. 일정 탭에는 전략 기간을, 예산 탭에는 전략별 한도·잔여를 표시한다. 계약·실제 지출·지급과는 별도의 계획 값이다.

기존 마이그레이션 4의 메타데이터 테이블 RLS 처리로 shadow DB에서 migrate dev가 실패했다. 적용된 마이그레이션을 변경하거나 데이터를 초기화하지 않고 Prisma migrate diff(기존/변경 datamodel)로 여섯 번째 additive migration을 생성하고 DB CHECK를 추가했다. Prisma migrate deploy로 검증한다.

검증: 전략 저장/수정/기존 값 보존, DB 제약, 고정 캠페인 한도와 활동 배정·수정·삭제에 따른 잔여 차감·복원, 전략 기간·예산 폼과 일정/예산 화면 연결, 모바일 표시를 검사한다. 명령은 npm run db:migrate:test, npm test, npm run test:integration, npm run test:e2e, npm run typecheck, npm run lint, npm run build이다.

2026-10-12 검증 결과: 단위 31개, PostgreSQL 통합 14개, 브라우저 E2E 4개(총 49개) 통과. 잔여 표시 검증과 모바일 스크린샷 보완 후 관련 E2E 2개를 다시 통과했다. TypeScript, ESLint, 운영 빌드 통과. Supabase 운영 DB에 여섯 번째 마이그레이션을 적용하고 실제 eruty_app 역할로 전략 기간·한도 보존, 활동 배정 20만 원 → 30만 원에 따른 캠페인 잔여 80만 원 → 70만 원, 삭제 후 100만 원 복원을 확인했다. 검증용으로 생성한 행만 제거하고 감사 기록은 남겼다. 기존 Supabase 보안 알림(마이그레이션 메타데이터의 정책 없음, Auth 유출 비밀번호 보호 꺼짐)에 변경은 없다.

스크린샷: `docs/screenshots/10-strategy-create.png`, `docs/screenshots/11-strategy-plan-mobile.png`. 실행은 `.env.example`을 복사해 DB/인증을 설정한 뒤 `npm ci`, `npm run db:migrate`, `npm run dev` 순서다. 운영 환경에서는 기존 Supabase 로그인 구성을 사용한다.

2026-10-13 집계 수정 검증: 캠페인 한도 250만 원, 전략 한도 10만 원 + 100만 원이면 전략 배정 110만 원, 캠페인 잔여 140만 원으로 계산한다. 활동 10만 원을 추가하거나 수정해도 캠페인의 전략 배정을 다시 차감하지 않는다. 전략 미설정/0원, 초과, JS 안전 정수를 넘는 합계를 검사했다. 단위 33개 + PostgreSQL 통합 14개 + 브라우저 E2E 4개(총 51개), TypeScript·ESLint·운영 빌드가 통과했다. 실제 운영 DB를 eruty_app 역할로 읽어 모든 캠페인의 전략 합계와 잔여를 확인했으며 데이터 수정이나 새 마이그레이션은 없다. API에 `allocatedStrategyKrw`, `unallocatedStrategyKrw`, `strategyOverBudget`, `unbudgetedStrategyCount`를 추가하고 기존 활동 계획 집계 필드는 유지한다. 새 스크린샷은 `docs/screenshots/12-campaign-strategy-budget.png`이다. 추가 라이브러리는 없다.
