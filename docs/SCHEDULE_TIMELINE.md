# 일정 개선 1차: 간트 조회

2026-10-20. 기존 일정 탭은 전략별 요약과 날짜 목록만 제공했다. 기존 WorkItem 계획 날짜, 전략 기간, 권한 API, 상세 패널을 재사용하여 간트 조회를 추가한다. DB 스키마 변경과 운영 마이그레이션은 없다.

React/React DOM 19.3 (MIT)와 CSS의 네이티브 버튼·표·스크롤로 구현한다. 새 라이브러리는 없다. [React 공식 문서](https://react.dev/reference/react), [MIT 라이선스](https://github.com/react/react/blob/main/LICENSE)를 확인했다. 2026-10-20 깨끗한 로컬 설치에서 npm audit 0건을 확인했다. 메이저 업데이트는 이번 일정 조회 변경에 포함하지 않는다.

구현 순서: 날짜 전용 좌표·범위·필터 함수 → 전략/활동/세부 작업 트리와 주/월 축 → 상세 패널·기존 수정 폼 연결 → 단위 및 브라우저 회귀 검증 → CI·운영 배포 확인.

- 주/월 표시, 전략/상태/겹치는 날짜 범위 필터, 계층 펼치기/접기, 오늘 표시, 기한 초과·캠페인 기간 밖 경고.
- 필터에 맞는 세부 작업의 상위 활동은 상태가 달라도 문맥으로 남긴다. 일치 개수에는 문맥용 상위 활동을 포함하지 않는다.
- 기간은 서울 기준 날짜 전용·양끝 포함으로 계산한다. 캠페인 밖 일정도 기본 조회 범위에 포함하며, 필터로 막대가 잘려도 전체 시작/종료일은 왼쪽에 남긴다.
- 날짜 역전 조회를 차단한다. 장기간의 축 눈금 수와 차트 폭은 제한한다. 좁은 화면은 차트 내부만 가로 스크롤하며 키보드와 버튼으로 상세/기존 날짜 수정이 가능하다.
- 조회·필터·확장에는 쓰기 API가 없다. 기존 실제 날짜·예산·감사 정책을 유지한다.

PR 2의 첫 번째 작은 변경이다. S7/S8의 조회 개선이며 드래그/리사이즈, 의존성·변경 영향 미리보기, 불변 기준 일정·실제 날짜 편집(S1–S6)은 후속 PR 범위다. PR 2 전체 완료를 주장하지 않는다.

실행: README의 로컬 PostgreSQL 설정 후 `npm ci`, `npm run db:migrate`, `npm run db:migrate:test`, `npm run db:seed`, `npm run dev`.

로컬 검증: Node 24.19, PostgreSQL 18.4, 단위 44개·실제 PostgreSQL 통합 16개 통과. 기존 브라우저 E2E 6개와 신규 간트 E2E 1개 통과. TypeScript·ESLint·운영 빌드 통과, npm audit 0건. 필터/주월 표시/펼치기 전후 데이터 동일·쓰기 요청 없음, 부모와 상태가 다른 세부 작업의 검색 문맥, 하루 일정·윤년·캠페인 밖 날짜·장기간 축, 날짜 역전, 키보드 상세 열기/닫기·포커스 복귀, 기존 폼의 날짜 저장·예산 보존, 390px 내부 가로 스크롤을 확인했다. 첫 신규 E2E에서 select 옵션이 label에 섞인 접근성 이름 문제를 발견해 고유 ID와 명시적인 label 연결로 수정했다.
