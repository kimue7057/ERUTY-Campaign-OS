# 버튼 아래에서 작성·수정

2026-10-20 사용자 요청: 캠페인 만들기는 목록 페이지 안에서 펼치고, 캠페인·전략·활동·세부 작업의 작성/수정은 누른 버튼 또는 행 바로 아래에서 처리한다.

기존 캠페인 상세는 하나의 EntityForm을 탭 위에 렌더링했고, 활동 상세의 수정 버튼도 패널을 닫고 그 공통 폼을 열었다. 캠페인 만들기는 별도 페이지로 이동했다.

구현 순서: 기존 폼을 재사용하는 앵커별 렌더링 → 목록 내 캠페인 작성 → 상세 패널 안 수정 → 간트의 전략 행 아래 추가 → 저장·취소·충돌·모바일 브라우저 검증 → PR·배포.

- 캠페인 수정은 제목/수정 버튼 줄 바로 아래, 전략 추가는 전략 추가 버튼 줄 아래, 전략 수정/활동 추가는 해당 전략 머리글 바로 아래에 펼친다.
- 활동 수정과 세부 작업 추가/수정은 해당 행의 바로 다음 행에 하나의 폼을 표시한다. 간트의 활동 추가도 해당 전략 행 바로 다음에 펼친다.
- 캠페인 수기 실적 입력도 해당 입력 버튼 바로 아래에 둔다.
- 활동 상세의 상태·일정·예산 수정은 패널 안에서 열리고 저장 후에도 패널을 유지한다. 저장 시 다른 작업을 잠그고 기존 revision·서버 검증을 따른다.
- 첫 입력은 페이지를 위로 이동하지 않고 포커스한다. 닫기/저장 후에는 누른 버튼으로 포커스를 돌린다. 편집 중 다른 편집·삭제 진입은 기존처럼 잠근다.
- 간트에서 작성 중인 폼이 검색 조건 변경으로 사라지지 않도록 필터를 잠근다. 탭을 이동하면 이전 탭의 편집 상태를 정리한다.
- 넓은 표에서는 입력 폼 너비를 스크롤 영역 너비에 맞추어 모바일에서도 입력을 위해 옆으로 이동할 필요가 없게 한다.
- 목록에서 캠페인을 저장하면 같은 목록에 표시한다. 기존 `/campaigns/new` 직접 주소는 같은 작성 컴포넌트로 유지한다.

React/Next.js(MIT) 및 기존 CSS를 사용하고 새 의존성·DB 모델·마이그레이션·API 변경은 없다. 기존 금액·일정·권한·감사 규칙은 그대로 사용한다.

검증: 단위 44개, 실제 PostgreSQL 통합 16개, 브라우저 E2E 8개 통과. 타입 검사·린트·운영 빌드 통과, npm audit 0건. 새 E2E는 목록 안 캠페인 생성·취소·재입력·저장, 버튼과 폼의 실제 좌표·DOM 순서, 아래쪽 전략에서 열 때 스크롤 위치 유지, 행 아래 활동/세부 작업 폼, 저장·취소·포커스 복귀, 모바일 390px 너비, 간트 내 추가, 상세 패널을 유지하는 수정, 금액·상태 저장을 확인한다. 기존 지연 저장 응답을 이용한 편집 경합 E2E도 통과했다.
