# Codex 구현 단계 / PR 단위

원칙: 각 PR마다 작동 확인 가능한 화면, DB/서버 검증, 관련 테스트, 실행 방법, 스크린샷을 포함하고 코드리뷰를 거칩니다.

## PR 1. 도메인 기반과 캠페인 골격
**목표**: Brand/Country/Campaign/Strategy/Activity/optional Subtask의 데이터 저장과 화면 이동.
- PostgreSQL+Prisma 채택 시 스키마/마이그레이션 및 seed 작성
- 캠페인 목록 -> 개요 -> 일정/예산 탭(자리 마련), 전략과 활동/세부 작업 CRUD
- 날짜·계층·소속 검증, 최소한의 내부 인증/인가 설계 및 서버측 검사
- 목표 순판매액/이루티 매출 독립 필드, DEMO 마킹
- 단위/통합 테스트 포함
**완료 기준**: `work_item` parent optional; 캠페인/전략/활동/세부 작업 CRUD 후 조회, 소속 검증 실패 케이스 차단. 직원별 업무 화면 없음.

## PR 2. 일정 간트 / 의존성 / 베이스라인
**목표**: 날짜와 의존관계를 안심하고 수정할 수 있는 작동형 일정 화면.
- 라이브러리 라이선스/접근성 검토 후 채택
- 주/월 줌, 계층 확장, 드래그 이동 및 양 끝 리사이즈, 키보드/폼 대안
- 선행/후속 FS+lag, 사이클 차단, 변경 영향 미리보기/명시 승인/취소
- baseline 스냅샷, 실제 시작·종료 구분, 변경 이력/지연 배지
- 낙관적 잠금/트랜잭션으로 충돌 방지
**완료 기준**: 원본 S1~S8 테스트 통과; 부적합 후속 작업은 자동 변경하지 않음.

## PR 3. 예산 계획 / 세부 작업 배분
**목표**: 예산 이중 합산 없는 계층별 계획과 공통 비용.
- activity budget lines, campaign common budget lines 및 세부 작업 allocation CRUD
- 전략/활동/캠페인 집계, 예산 한도/미배정/초과 표시
- 예산 수정 사유와 버전 기록, KRW bigint-safe
**완료 기준**: B1-B3, B10-B11 중 계획 영역 통과.

## PR 4. 계약/비용 원장/부분 지급/증빙
**목표**: 지출 전체 생애주기 관리.
- Commitment -> linked expense -> cleared/reversed payments 모델
- 승인/취소 감사 로그, 증빙 업로드 권한/다운로드 제어
- 외화 금액·확정 환율·KRW 변환 스냅샷, VAT 정책 노출
- 원장 필터/CSV 내보내기, 캠페인 요약/드릴다운
**완료 기준**: B4-B9와 B11 통과. 계획/확약/비용/지급액 섞지 않음.

## PR 5. 통합 품질/보안/문서
**목표**: 전체 기능의 정확성 검증.
- summary drilldown, role checks, idempotency, index/perf 점검
- E2E 간트 드래그/폼 대안/재무 CRUD 테스트
- 1440px 및 좁은 화면 테스트, 한글 UI/오류 메시지, 린트·빌드·테스트
- 환경변수/마이그레이션/배포 지침, 제약 사항 명시
**완료 기준**: Spec S1~S8, B1~B11, Q1~Q5 통과. 미달 항목 명시.

### 제외 / 다음 차수
직원별 개인 업무 화면, 재고/물류, 매출 API, 실제 계약 자동 매출 인식, AI 분석/예측, 외부 파트너 포털.
